# 작품 살펴보기

분석을 읽는 데 드는 수고가 글을 쓰는 수고보다 커지지 않게 한다. 편집기와 작품 메뉴의 **작품 살펴보기**에서 네 화면을 탭으로 오간다. 탭을 옮길 때 원고·장 문맥을 유지한다. 등장인물의 **관계 그래프**는 해당 인물을 중심으로 연다.

## 이야기 흐름

시작·전환점·절정·마지막 사건의 제목을 최대 6개씩 보여 준다. 모든 사건은 별도로 선택한다. 하나를 고르면 그 사건의 요약과 직접 연결이 열린다. 연결은 먼저 2개까지만 보인다. 시간순 선과 인과관계를 구분하고, 서버의 알 수 없는 관계를 원인으로 바꾸지 않는다.

분석은 사용자가 명시적으로 시작한다. 다시 분석하는 동안 이전 결과를 읽을 수 있고, 다른 화면에 다녀와도 같은 탭에서는 원고별 작업을 이어서 확인한다. 통신 실패는 빈 결과와 구분한다. 현재 API에는 문장별 근거 위치가 없어 원문 링크는 확인 가능한 장에만 제공한다.

## 인물 관계

중심 인물과 직접 연결된 최대 6명의 관계만 그린다. 인물을 누르면 중심이 바뀌고, 관계를 누르면 상태와 기록이 열린다. 장 슬라이더는 그 시점까지 기록된 마지막 상태를 보여 준다. 아직 기록되지 않은 미래 상태나 없는 인물을 그리지 않는다. 변화 기록과 관리 동작은 별도로 펼친다. 모바일에서는 세로 가지 형태로 배치한다.

real 모드에서는 RCV 서버 API를 사용한다. 원고를 선택하고 실제 `chapter_id`로 기록하며, 조회는 `manuscript_id`로 이력을 분리한다. 같은 번호의 장이 다른 원고에 있어도 섞이지 않는다. 인물 쌍은 프로젝트 단위로 공유하고 원고별 첫 기록을 추가할 수 있다. 관계 삭제는 모든 원고의 이력을 삭제하므로 확인창에 그 범위를 표시한다.

백엔드 `codex/relationship-integration`이 필요하다. 저장·삭제는 editor 이상, 조회는 viewer 이상이다. 같은 장의 중복 기록은 409로 확인 후 덮어쓴다. 연결된 관계가 있으면 인물 삭제를 막는다. 메모는 실제 사건 리소스의 링크로 취급하지 않는다. RCV 명세상 수동 기록 기능이며 AI 자동 추출은 범위에 없다. mock 모드만 시연용으로 표시한다.

## 복선

처음에는 미회수 복선만 최대 6개씩 표시한다. 점선은 미회수 구간, 실선은 회수까지의 구간이다. 복선을 고르면 설명·심은 장면·이어진 장면·회수 장면을 보여 준다. 미회수 안내와 관리 동작은 별도로 펼친다.

실제 모드의 원문 링크는 백엔드 장 ID를 실제 원고에 대조해 만든다. 같은 장 번호가 다른 원고에도 있어도 임의로 연결하지 않는다. 연결·회수·수정도 복선을 심은 원고의 장 ID를 사용한다. 새로운 복선은 기존 API와 같이 최신 ready 원고에 작성한다. 설치 장이 삭제된 복선은 0장으로 그리지 않는다. 비슷한 복선 안내에서 새 복선을 자동 삭제하거나 병합하지 않는다.

복선은 저장된 기록을 시각화하며, 자동 추출 결과라고 표시하지 않는다. 기존 FTS 서버 API와 연결된다.

## 설정 검토

처음에는 후보 목록만 보여 주고, 선택한 후보의 두 근거를 비교한다. AI 조언은 필요할 때 펼친다. 기존 검사·수정·검토 처리 API를 유지한다.

편집기에서는 현재 장의 미검토 결과를 옅은 붉은 물결 밑줄로 표시한다. 누르면 해당 설정과 설명만 작은 카드로 열고, 무시하거나 상세 검토 화면으로 이동한다. `설정 검사`는 저장을 마친 현재 장만 검사한다. 입력할 때마다 AI를 호출하지 않는다.

실제 장 ID와 검사한 원문이 일치하는 결과만 표시한다. 서버가 위치를 특정하지 못한 결과, 다른 원고의 같은 장 번호, 여러 곳에 반복되어 문맥으로 구분할 수 없는 문장은 밑줄을 그리지 않는다. 수정한 문장은 기존 근거와 일치하지 않으면 즉시 표시를 지운다. 겹친 결과는 밑줄 하나로 묶고 카드에서 각각 읽는다. 맞춤법 검사가 아닌 기존 SCDS 설정 충돌 결과의 표시다.

textarea를 유지하고 별도 층에 밑줄을 그린다. 한글 조합 중에는 밑줄과 자동 저장을 잠시 멈춘다. `검토 N곳`과 다음 버튼으로 키보드에서도 근거를 열 수 있고 Escape로 닫는다.

## 확인

`npm run test:insights` (Node 22.18 이상): 이야기 흐름, 관계 시점, 인물 수 제한, 페이지 경계, 삭제된 복선 장 위치, 원문 밑줄의 장 ID·문맥·UTF-16 위치·수정 후 무효화를 검사한다.

실제 로컬 PostgreSQL·FastAPI와 연결해 브라우저에서 관계 생성 → 장별 기록 → 새로고침 후 조회를 확인한다. Google 인증만 로컬 검증용 대체 인증을 쓴다. 백엔드 테스트는 별도 `_test` DB에서 실행하며 중복·경합·페이지네이션·원고 분리·권한·다른 프로젝트의 참조 차단을 포함한다. 실제 LLM 결과 검증에는 별도 OpenRouter 키가 필요하다.
